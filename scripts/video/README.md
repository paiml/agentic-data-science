# scripts/video: recorder settings and the recording check (vcheck)

One shared place for the terminal-recording fix (font spacing, plot legibility); courses source it instead of copying it.

- `cell.env`: cell 14x34 (glyph pitch/ink ratio about 1.17; the old 20x28 gave 2.14 by the audit, 2.22 on the stills), 137x31 cells, plot at x=1200, 720x1080.
- `lib.sh`: `cell_args`, `video_args`, `layout_rects`, `layout_from_tmux`, `layout_write` for recorders (bash only).
- `compose.sh rec.termctrl plot.png out.mp4 [rec-layout] [plot.meta]`: renders, pads to 1920x1080, overlays the plot at the plot-shown mark, writes `out.mp4.layout`.
- `vcheck.sh video [layout] [--gate] [--sidecar-only] [--lossless png] [--shown S]`: prints `CHECK <name> PASS|FAIL|N/A` and `VERDICT`; exit 1 on FAIL. `N/A` is printed only without `--gate`/`--sidecar-only`, for a check whose input is absent; under `--gate` an unmeasurable check is FAIL, never `N/A`.
- `tests/run.sh [workdir]` (`make test-video`): **143 proofs** on synthetic takes built from real-renderer fixtures (`tests/gen.sh`, `tests/regen-fixtures.sh`): 63 take rows (6 must-PASS, the rest must-FAIL on named checks), 18 guard-message proofs, 36 sidecar missing/empty proofs (18 required keys x 2), 1 empty-core proof (all four T-lines FAIL), 12 malformed-value proofs (fit_rgb x2, non-numeric float x2, beats name and window x3, non-integer, rect, axis, tick), 2 `--sidecar-only` without-layout proofs, 1 workflow-text proof (`--state all` marker query), 10 `lab.sh` proofs (no/empty takes dir, stub error, `.base.mp4` skipped, ...). Runs the rows in parallel (`JOBS`, default 12) with the pixel core at `CORE_FPS=2`; about 6 minutes on 32 cores. CI: `make test-video` runs as ordinary tests in the `datasets` job (synthetic takes only; no recordings). `make lab-video` (`lab.sh`: `vcheck --gate` on real takes) runs only in the nightly `video-lab` workflow, which is Nightly: one ticket with one owner on red, self-disables after 7 non-green nights, never in a PR check. A recording still needs a vcheck PASS before a take counts.
- `tests/real-stills.sh [dir]`: local negative proofs on the audit's real stills (Rust t02/t37, Lean v3 t16): font-spacing FAILs at 2.22 on all three, plot-legibility FAILs on t37, and the lib.sh `rect.code` / `rect.watermark` pair has no overlap on all three (7 proofs). Not in CI (the stills are private evidence); it prints not_measured and exits 1 if they are missing. T3, T2pre and box do not fail on these stills (line pitch is 28, no early pane edge); their negative proofs are the synthetic `bad-pitch24` and `bad-prediv` takes.

## Checks
- `input`: 1920x1080, 20 fps, non-empty (a non-numeric duration is not a duration). `sidecar`: every required key present, non-empty and well-formed (rects `x,y,w,h`, axes `lo,hi`, integers, seconds); a missing layout is FAIL under `--gate` and under `--sidecar-only`; a core that fails prints `core FAIL` once and every T-line as FAIL.
- `T3` (line pitch >= 28), `T2pre` (no divider before the plot), `box`, `T2post` (plot edge >= 1056 from shown+0.25 s); an empty pixel-core summary is FAIL, never skipped.
- `pane-edge`: sidecar `plot_pane_left_px` >= 1056. `cell`: `cell_w`x`cell_h` must equal `cell.env` (14x34).
- `font-spacing`: glyph pitch/ink 1.05..1.35 and line/x-height >= 1.8, on a LOSSLESS frame (`<take>.mp4.frame.png` written by compose, or `--lossless`); a gate take without one is FAIL. `dim-luma`: dimmest fifth of the text lines >= 55% of the brightest. `reveal-shift`: code pane moves <= 2 MAD between 0.15 s before and after the reveal.
- `plot-legibility` (on `rect.axes`): fit line thickness >= 2 px, continuity, contrast, a fit colour that is not the background (Chebyshev >= 60) and not the grid (>= 40) (white or yellow passes), axis span 80..~100% of the axis with the data inside it, no watermark overlap with code/title/legend/plot. `plot-text`: title and legend >= 26 px (25 measured), ticks >= 22 (21 measured), title ink top y >= 72, legend fit swatch >= 20 px, declared `tick_px` within 4 px of the measured value. `watermark`: top-right, y+h <= 72. `hold-fade`: the final hold keeps >= 90% of its luma.
- `beats` (required): `cargo_toml`, `tree`, `version`, `call`, `stdout` all declared and measured: `[dependencies]` (not dev-deps, `[dependencies.x]` tables included) holds an exact `aprender` (`aprender-viz` does not count) and any dependency beyond polars/aprender/aprender-viz carries a `# reason`; `cargo tree` shows `aprender vN`; `--version`; a visible `aprender::path(`/`aprender::path!`/`aprender::path::<` call on a line that is not a `use`; stdout with a number and unit. Each beat window is >= 4 s, sequential, and the code pane holds still through it.
- `frozen`: no still stretch > 3.5 s OUTSIDE the declared beat windows (the `beat.<name>=start,end` windows; the recorder hides the cursor, so a held beat is bit-identical and `beats` requires 4..8 s of it: an uncapped window would exempt any freeze); the final hold (the run reaching the end, measured whole) 2.5..3.5 s. Proofs: a synthetic take built from real-renderer fixtures, cursor hidden as the recorder does, passes both (`good-real`); a 5 s still outside every window FAILs (`bad-still-outside`, `bad-freeze`); a beat held 3 s FAILs `beats` (`bad-real-short`).
- `watermark`: the PREVIEW mark sits in the top-right corner of the frame (`lib.sh layout_rects`: 200x40 at x=1706, y=16), over the plot pane and above the plot title (y+h <= 72, x >= `plot_pane_left_px`), so it can never overlap `rect.code`, which ends two cells before the plot pane; `gen.sh` writes the same two rects through the same function.

## Layout sidecar
`key=value` lines, last occurrence wins. Required keys: `cell_w cell_h shown_s plot_pane_left_px rect.code rect.plot rect.axes rect.title rect.legend rect.ticks rect.watermark fit_rgb axis_x axis_x_data axis_y axis_y_data tick_px beats` (`beats=name,name,...` plus one `beat.<name>=<start_s>,<end_s>` line per beat, each 4..8 s; fit_rgb is six hex digits; numbers are plain decimals; snapshots in `<layout>.beats/<name>.txt`). The recorder writes the pane geometry (`lib.sh`), the chart writes its own metadata (`plot.meta`), compose adds `shown_s`, `rect.plot` and copies the beats. With `--gate` a missing sidecar or any missing/empty key is FAIL (not measured).

## Limits
- n7 (same-background empty margin) is invisible to pixels; only the sidecar pane-edge check catches it.
- Fit colour, tick size and beat windows are declared by the recorder and then MEASURED against the frame; a sidecar that lies is caught only where the measure disagrees.
- CI runs synthetic equivalents; real takes are local evidence only. The nightly lane needs the repo variable `VIDEO_TAKES` (a runner directory); unset, it is red (not_measured) by design.
- T3, T2pre and box do NOT fail on the real stills (Rust t02/t37, Lean v3 t16): their line pitch is 28 and no early pane edge is drawn, so the earlier measurement's "each check FAILs on t02/t37/Lean v3" holds for `font-spacing` and `plot-legibility` (t37) only. T3, T2pre and box rest on the synthetic bad-pitch24 and bad-prediv takes. No real 14x34 still passes `plot-legibility` yet (the re-rendered Rust plot has a 1 px fit); every must-PASS proof is synthetic.
- `beats` are measured on the recorder's snapshot files, which are not tied to the video frames: a blank pane with fabricated snapshot text would pass. Snapshot text is not OCR'd: only that the pane holds still in each window is measured on the frames, so this must close before `beats` could become a GATE. `call` ignores `use` lines and `stdout` ignores `Compiling/Finished/Running/Blocking/Downloaded` lines; any other `0.42s` still satisfies `stdout`.
- The watermark rect is declared by the recorder and checked for geometry (top-right, no overlap with `rect.code`); `tests/real-stills.sh` checks the `lib.sh` arithmetic, not watermark pixels.
- The font frame (`<take>.mp4.frame.png`) is written by the same recorder run but is not hashed to the take.
- `video-lab.yml` counts 7 non-green scheduled nights after the last `video-lab:disabled` marker comment on any video-lab ticket, open or closed; a disable that found no ticket leaves no marker, and a re-enable without a marker is invisible to it.
